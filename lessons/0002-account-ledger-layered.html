第 2 课 · 账户与账务

Phase 0 巩固 CEX · 用 decimal 建内部账本 + 把单文件 main.go 重构成分层结构

本课目标：跑通「开户 → 充值（mock）→ 查余额」的最小账务闭环，并学会用 decimal 处理金额。同时把代码从「一个 main.go」拆成 领域层 / HTTP 层 / 装配层 三层。

① 流程图（本课点亮「账户/账务」）

本课三个接口：POST /accounts（开户）、GET /accounts/:id/balance（查余额）、POST /accounts/:id/deposit（内部充值，先不碰链，链在 Phase 4 才接）。

② 整体思考（先想清楚）

1. 金额绝不能用 float

0.1 + 0.2 在二进制浮点里 ≠ 0.3。金融系统用定点数表示金额（本质是整数分 / 字符串），Go 里用 github.com/shopspring/decimal。

前端类比：你从不会用 0.1 + 0.2 === 0.3 做金额判断，而是用整数「分」或 decimal.js。Go 这边是同一个道理——金额字段类型一律 decimal.Decimal，绝不 float64。

2. 「账户」是快照，「流水」是不可变记录

概念是什么前端类比
Account（余额）当前余额的快照React 里的 state
LedgerEntry（流水）每一笔变动的不可变记录（谁、多少、方向、时间、原因）每次 setState 的 action 日志（Redux / event log）

余额可由流水 replay 出来。生产里 Ledger 是 append-only（只追加、永不改删），它是审计、对账、回滚的唯一真相源。本课先用内存切片存流水，建立这个心智。

3. 为什么现在用「内存 map」而不是数据库

「跑通整体流程」优先。数据库（PostgreSQL）后面再接。但结构上要预留换存储的余地——所以业务规则放在 internal/account，它只依赖自己持有的 struct，不直接散落全局变量；以后把 map 换成 DB 只改这一层。

4. 为什么要分层

第 1 课把所有东西塞进 main.go，模块一多就失控。本课拆三层：

层目录职责前端类比
领域层internal/account(model+service)业务规则（开户/充值/余额），与 HTTP 无关，可单测纯函数 / store
HTTP 层internal/account/handler.go协议转换（JSON ↔ 调 service），按模块就近放、各自 RegisterRoutescontroller / route handler
装配层cmd/server/main.go
+ internal/server（引擎+中间件，后续引入）		建引擎 → 各模块 RegisterRoutes → Run，不含逻辑入口装配

③ 引导敲码（分 5 步，每步给路径 + 目标 + 提示）

本课文件结构（在 minicex/project 下）：

project/

Step 1 — internal/account/model.go：先定义数据形状

  • 目标：写出 Account 和 LedgerEntry 两个 struct，金额字段类型是 decimal.Decimal（不是 float64）。
  • 骨架：
package account

import (
    "time"
    "github.com/shopspring/decimal"
)

type Account struct {
    ID        string
    UserID    string
    Balance   decimal.Decimal // ⚠️ 不是 float64
    CreatedAt time.Time
}

type LedgerEntry struct {
    ID        string
    AccountID string
    Amount    decimal.Decimal // 正数=入账，负数=出账
    Type      string          // "deposit" / "withdraw"
    Note      string
    CreatedAt time.Time
}
填空提示：给 Account 加一个 Currency 字段（如 "USDT"）——想想为什么一个用户可能要有多币种账户。

Step 2 — internal/account/service.go：领域逻辑 + 存储

  • 目标：一个 Service struct 持有 accounts map[string]*Account 和 ledger []LedgerEntry，加 sync.Mutex 防并发；提供三个方法。
  • 骨架（方法体你来实现）：
package account

import (
    "sync"
    "github.com/google/uuid" // 或自己生成 ID
    "github.com/shopspring/decimal"
)

type Service struct {
    mu       sync.Mutex
    accounts map[string]*Account
    ledger   []LedgerEntry
}

func New() *Service { /* 初始化 map 并返回 */ }

func (s *Service) OpenAccount(userID string) *Account { /* 余额从 0 起 */ }

func (s *Service) GetBalance(id string) (decimal.Decimal, error) { /* 不存在返回 error */ }

func (s *Service) Deposit(id string, amt decimal.Decimal, note string) (*LedgerEntry, error) {
    // 思路：1) 加锁  2) 查账户，不存在报错
    //       3) Balance = Balance.Add(amt)   4) 追加一条 LedgerEntry
    //       5) 解锁并返回
}
Go 小提示：decimal 加法是 balance.Add(amt)，不是 +；校验金额可用 amt.IsNegative()。并发读写 map 会 panic，所以每个方法进出都要 mu.Lock() / mu.Unlock()（或用 defer mu.Unlock()）。

Step 3 — internal/account/handler.go：HTTP 适配（按模块就近放）

  • 目标：三个 Gin handler，把请求 JSON ↔ 调 Service，返回 JSON。handler 与 service 同属 package account（模块自洽），不写业务规则，只做协议转换 + 挂路由。
  • 骨架：
package account   // ⚠️ 和 service.go 同包，不再单独开 server 包

import "github.com/gin-gonic/gin"

type Handler struct{ svc *Service }   // 同包内直接用 *Service，无需 import

func NewHandler(svc *Service) *Handler { return &Handler{svc: svc} }

// 模块自己把路由挂上去，main.go 只调用这一行
func RegisterRoutes(r gin.IRouter, svc *Service) {
    h := NewHandler(svc)
    r.POST("/accounts", h.OpenAccount)
    r.GET("/accounts/:id/balance", h.GetBalance)
    r.POST("/accounts/:id/deposit", h.Deposit)
}

func (h *Handler) OpenAccount(c *gin.Context) { /* POST /accounts */ }
func (h *Handler) GetBalance(c *gin.Context)  { /* GET /accounts/:id/balance */ }
func (h *Handler) Deposit(c *gin.Context)     { /* POST /accounts/:id/deposit */ }
填空提示：用 c.ShouldBindJSON(&req) 收 JSON 体、c.Param("id") 取路径参数、c.JSON(status, data) 回包。金额从 JSON 进来时是字符串（如 "10.5"），用 decimal.NewFromString() 解析。handler 与 service 同包，可直接访问 svc 的私有字段；模块变大、handler 很多时，可把 HTTP 部分拆成 account/http/ 子包隔离（可选）。

Step 4 — cmd/server/main.go：只装配

  • 目标：把 service 和 handler 连起来、挂路由、Run。第 1 课的 main.go 整体替换为这个分层版本（/ping 可保留可删）。
  • 骨架：
package main

import (
    "github.com/gin-gonic/gin"
    "minicex/internal/account"
)

func main() {
    svc := account.New()

    r := gin.Default()
    account.RegisterRoutes(r, svc)   // 每模块各自挂载，加模块只多一行
    r.Run(":8080")
}
为什么这样拆：handler 不再集中到 internal/server，而是每个模块自带 RegisterRoutes。以后加 match / deposit / withdraw 模块，main.go 只是多一行 xxx.RegisterRoutes(r, svc)，不会退化成上帝文件。internal/server 这个包保留给「引擎创建 + 全局中间件（JWT 等）」，到第 3 课接入鉴权时再引入。

Step 5 — 跑起来 & 拉依赖

  • 命令：在 project 下执行 go mod tidy && go run ./cmd/server。
  • go mod tidy 会自动把 gin、decimal、uuid 写进 go.mod。看到 Listening and serving HTTP on :8080 即成功。

④ 跑通校验

另开终端，三连击：

# 1) 开户
curl -X POST localhost:8080/accounts -H 'Content-Type: application/json' -d '{"user_id":"u1"}'
# → {"id":"...","user_id":"u1","balance":"0","currency":"USDT"}

# 2) 充值 10.5（mock，不走链）
curl -X POST localhost:8080/accounts//deposit -H 'Content-Type: application/json' -d '{"amount":"10.5","note":"test"}'
# → {"amount":"10.5",...}

# 3) 查余额
curl localhost:8080/accounts//balance
# → {"balance":"10.5"}
跑通标准：balance 返回的是字符串 "10.5"，不是浮点 10.5。✅ 这一步确认 decimal 生效——这是后面链上充值/对账安全对齐的基石。

⑤ 生产 reality（⚠️ 可选扩展，留到 C 阶段）

知道「真实环境还会考虑这些」即可，本课不深挖。
  • 金额序列化：decimal 默认 JSON 是字符串，前端要按字符串处理；或自定义 MarshalJSON 成整数「分」避免精度歧义。
  • 并发边界：mutex 只在单进程有效；多实例要换 DB 事务 / 行锁（PostgreSQL UPDATE ... SET balance = balance + $1）。
  • 流水不可变：生产里 Ledger 是 append-only 表，绝不允许 UPDATE/DELETE，余额由流水推导。
  • 账户隔离：一个用户多币种 = 多个 Account（或 account 加 currency 维度），资金调拨要走内部转账流水。
  • ID 生成：本课用 uuid 图省事；生产多用雪花 ID（有序、利于索引）。
