② 整体思考（先想清楚再敲）

为什么用 Gin？

你是前端，Gin 类比一下就懂：

Go / Gin前端对应作用
gin.New() / gin.Default()const app = express()创建应用实例
r.GET("/x", h)app.get("/x", h)注册路由
gin.Context请求上下文 ctx / req+res一次请求的输入输出
r.Use(mw)app.use(mw) 中间件横切逻辑（日志/鉴权）
c.JSON(200, x)res.json(x)返回 JSON
关键心智：Gin 的 handler 就相当于你熟悉的 controller / route handler；middleware 和 Express/Koa 中间件一模一样。你不是从零学 web，是把已有心智映射到 Go 语法。

main.go 应该保持很小

新手常把路由、业务逻辑、配置全塞进 main.go。本课允许（因为只有 /ping），但记住纪律：main 只做「装配」——创建服务、挂路由、启动。业务逻辑往后要挪进 internal/。第 2 课就动手分层。

③ 引导敲码（分 5 小步，每步只给目标 + 提示）

本课只在项目根建两个文件：project/go.mod 和 project/main.go。

要求：下面每一步的「目标」你要自己敲出来。唯一需要你写代码的是第 4 步（hello-world 量级）。敲的时候想清楚每一行对应流程图里哪一块。

Step 1 — 建目录 & 初始化模块

  • 目标：进入 minicex/project，让 Go 把它当一个 module。
  • 提示：执行 go mod init minicex。会生成 go.mod。module 名用 minicex 即可（本地产练习，不要域名）。
  • 校验：目录里出现 go.mod，内容含 module minicex。

Step 2 — 拉 Gin 依赖

  • 目标：让项目能用 github.com/gin-gonic/gin。
  • 提示：执行 go get github.com/gin-gonic/gin。Go 会自动把依赖写进 go.mod / go.sum。

Step 3 — 想清楚 main.go 要做什么

  • 创建 Gin 引擎；
  • 注册一条 GET /ping 路由，返回 {"message":"pong"}；
  • 启动在 :8080。

Step 4 — 手写 main.go（本课唯一需要你写的代码）

  • 骨架提示（按这个结构补，不要抄一大段）：
package main

import "github.com/gin-gonic/gin"

func main() {
    r := gin.Default()          // 创建引擎（≈ express()）
    r.GET("/ping", func(c *gin.Context) {
        c.JSON(200, gin.H{       // gin.H 就是 map[string]interface{}
            "message": "pong",
        })
    })
    r.Run(":8080")               // 启动监听
}
敲完问自己：这一行 r.GET("/ping", ...) 在流程图里是哪一块？它把「客户端请求」连到了哪个「处理动作」？

Step 5 — 跑起来

  • 命令：go run .（在 project 目录下）。
  • 看到 Listening and serving HTTP on :8080 即成功，终端会阻塞——这是正常的，Ctrl+C 退出。

④ 跑通校验

另开一个终端，确认服务真的在响应：

curl localhost:8080/ping
# 期望输出：
# {"message":"pong"}
跑通标准：浏览器或 curl 访问 /ping 返回 {"message":"pong"}。✅ 第一课完成。

⑤ 生产 reality（⚠️ 可选扩展，不转移主线）

以下都属于 C 阶段。本课只需跑通，知道「真实环境还会考虑这些」即可，不要现在深挖。
  • 优雅退出：生产用 r.Run 不够，要监听 SIGTERM 平滑关连接（避免正在处理的请求被砍）。
  • 配置外部化：端口、环境变量用 viper 或标准 flag/os.Getenv，不写死。
  • 结构化日志：用 log/slog 代替 fmt.Println，方便 ELK 收集。
  • 微服务化：真实交易所账户/撮合/风控是独立服务（gRPC 内通），不是单体 main。
  • 链路追踪：OpenTelemetry 串联一次请求跨服务。
